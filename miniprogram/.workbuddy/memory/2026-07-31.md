## 对话测定加入「防印象管理偏差」机制

### 需求
用户指出：测定功能位时不能按用户偏好，否则会被误导。例如用户可能因"慕劣势功能"而刻意回避谈论具体感官体验，转而大谈抽象模型以显得"有深度"，导致 AI 把伪装功能误判为主导。

### 实现
在 config/llm.js 的 SYSTEM_PROMPT 中新增【防印象管理偏差（核心测定学原则）】模块，包含 6 条原则：
1. 行为采样优于自陈——不采信"我擅长抽象思考"等自述，只采信讲述事件时的真实思维轨迹
2. 识别印象管理信号——理论术语自我标签化、回答过于工整、刻意引导回避反方向、自述与行为脱节
3. 反向追问策略——用户往哪装就往反方向追（大谈抽象→逼问感官细节；强调效率→逼问内在价值等），但语气保持好奇而非审问
4. 回避即信号——反复回避某类追问本身就是该功能处于劣势位的强信号
5. 跨情境一致性验证——同一功能至少在 2 个不同情境一致才提高置信度
6. 压力情境采样——追问冲突/紧急/意外中的第一反应，印象管理在此最易崩塌

### 掌握度封顶规则
更新掌握度评估标准：检测到明显印象管理且未通过行为采样打破前，掌握度封顶 50（不论聊多少轮）。升到 70 以上需满足：至少 3 个功能通过行为采样验证、无明显回避模式、跨至少 2 类情境一致。

### 设计决策
- 不在 UI 上显示"检测到印象管理"——会让用户防御性更强、强化伪装，违背"感觉在被理解而非被测试"原则
- 通过掌握度封顶机制自然让用户"多聊几轮"，AI 建议会引导往具体行为方向聊，自然打破伪装
- 只改 config/llm.js，元信息块格式不变，客户端无需改动

### 修改文件
- config/llm.js — SYSTEM_PROMPT 新增防印象管理模块 + 掌握度封顶规则

## 关键修正：createModel 参数（404 根因）
hy3 返回 404 Not Found，根因是 createModel 参数写错了。

wx.cloud.extend.AI.createModel() 的参数是 **provider/GroupName**，不是模型名！

正确用法：
```js
const model = wx.cloud.extend.AI.createModel("cloudbase")  // provider
model.streamText({ data: { model: "hy3", messages: [...] } })  // 具体模型
```

错误用法（之前写的，导致 404）：
```js
createModel("hunyuan")  // ← 错！这是 vendor 名
createModel("deepseek")  // ← 错！这也是 vendor 名
```

三种合法的 createModel 参数：
- "cloudbase" — 默认，多模型池（hy3/deepseek 等都走这个）
- "hunyuan-exp" — 小程序成长计划专用（已废弃，迁移到 cloudbase+hy3）
- "custom-xxx" — 用户自定义 GroupName

config/llm.js 更新：
- AI_PROVIDER: 'cloudbase'（createModel 参数）
- AI_MODEL: 'hy3'（streamText 的 model 字段）
- 移除了 AI_MODEL_ID（不再需要）

同步更新了：llmService.js、llm-chat/index.js、llm-chat/config.js

## 恢复聊天记录后自动补发AI回复
用户需求：恢复记录后如果最后一条是用户消息（AI还没回复就退出了），自动调用一次AI。

实现：
- onLoad 恢复历史记录后检查最后一条消息的 role
- 如果是 'user' 且非 error，延迟500ms后调用 resumeAIResponse()
- resumeAIResponse(): 插入AI占位消息 → 调用AI流式输出 → 更新掌握度 → 保存记录
- 逻辑与 onSend 的AI调用部分一致（复用流式回调、insight解析、保存逻辑）

## 修复：用户消息重复发送（2次 user 消息）
用户截图发现请求体里 user 消息重复了。

根因：
- onSend 把 user 消息加进 this.data.messages
- 然后从 this.data.messages 构造 history 传给 AI
- AI 内部又把 userMessage append 一次
- 结果 user 消息在 messages 数组里出现两次

修复：llmService.js 检测 history 最后一条是否就是当前 userMessage，是则不 append。
