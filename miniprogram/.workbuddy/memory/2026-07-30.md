## 对话测定加入「信息掌握度」反馈机制

### 需求
用户希望对话进行几轮后，AI 每轮返回当前掌握信息的程度，方便用户判断是否继续聊天、何时可生成报告。

### 实现方案
通过 System Prompt 让 AI 从第 3 轮起在每轮回复末尾附带结构化元信息块（用 `<!--INSIGHT-->...<!--/INSIGHT-->` 标签包裹），客户端解析后剥离正文、单独展示掌握度。

### 元信息块格式
```
<!--INSIGHT-->
掌握度:65
荣格倾向:Ni>Fe>Ti>Se
九型倾向:4号
建议:可以继续聊聊你做决定时的场景
<!--/INSIGHT-->
```

### 修改文件
1. `config/llm.js` — 扩展 SYSTEM_PROMPT 加入掌握度输出规范；新增 INSIGHT_START_ROUND=3、INSIGHT_READY_THRESHOLD=70 配置
2. `utils/llmService.js` — 新增 parseInsight/stripInsightBlock/safeStreamContent/safeOutputLength 函数；改造 sendChatMessage 流式逻辑，自动剥离元信息块并返回 insight 字段
3. `pages/chat-assessment/chat-assessment.js` — 新增 insight 相关 data 字段；onSend 中处理 result.insight 更新进度；onEndChat 掌握度达标时允许提前生成报告
4. `pages/chat-assessment/chat-assessment.wxml` — 进度区增加信息掌握度条+倾向标签+建议；AI 气泡下方加小标签；导航"完成"按钮 ready 时变"生成报告"
5. `pages/chat-assessment/chat-assessment.wxss` — 新增 insight-section/bubble-insight 等样式

### 关键技术点
- 流式输出时用 safeOutputLength 检测末尾是否疑似 `<!--INSIGHT-->` 前缀，暂缓输出避免用户看到标签碎片
- 字段解析用 indexOf(':') 定位冒号，避免硬编码中文字段名长度（曾因此出 bug：荣格倾向/九型倾向是 4 汉字+冒号=5 字符，误用 substring(4)）
- 8 个单元测试用例全部通过（标准/无元信息/流式中途/标签碎片/边界值/非INSIGHT的<!--等）
