# MBTI Match 项目改造方案

> **核心目标**：将传统做题式 MBTI 测试小程序，改造为基于大模型对话的荣格八维认知功能测定工具，并构建渐进式学习路径与商业化体系，服务于休学/抑郁状态青少年及其家长群体。

---

## 一、项目愿景与定位

### 1.1 产品定位转变

| 维度 | 改造前 | 改造后 |
|------|--------|--------|
| 测定方式 | 12 题二选一做题 | 大模型自然对话测定 |
| 理论基础 | 4 维度字母组合 | 荣格八维认知功能栈 |
| 结果深度 | 4 字母 + 标签 | 8 功能强度排序 + 证据链 |
| 用户关系 | 一次性测试工具 | 长期成长陪伴伙伴 |
| 目标人群 | 泛 MBTI 爱好者 | 休学/抑郁青少年及家长 |
| 商业模式 | 无 | 分层订阅 + 内容付费 |

### 1.2 核心理念

**"不是测你是谁，而是陪你看见自己如何思考"**

传统 MBTI 测试的根本问题：
- **自陈偏差**：用户回答"理想自我"而非"真实自我"
- **强制选择**：现实情境远比二选一复杂
- **静态结果**：人格是动态发展的，标签固化反而有害
- **忽略过程**：只看结论，不看认知过程

对话式测定的优势：
- **行为采样**：从用户真实的语言、决策、关注点中提取认知模式
- **情境还原**：通过真实场景对话观察功能运用
- **动态适配**：根据回答智能调整后续探查方向
- **温度感**：尤其对抑郁/休学群体，对话本身就是疗愈的开始

### 2.2 关键技术决策

| 决策点 | 方案 | 理由 |
|--------|------|------|
| LLM 调用位置 | **云函数代理** | API Key 绝不能放客户端；云函数天然支持鉴权、限流、日志 |
| 对话状态管理 | **云端会话 + 本地缓存** | 云函数维护完整对话历史，客户端本地缓存用于离线展示 |
| 测定逻辑 | **LLM 分析 + 规则校验** | LLM 负责语义理解和功能识别，规则层保证结果符合荣格理论约束 |
| 流式输出 | **SSE 流式** | 提升对话体验，尤其长回复场景；通过云函数转发 |
| 用户数据 | **云数据库 + 本地 storage** | 敏感数据上云（需用户授权），本地缓存提升体验 |
| 模型选择 | **混元 Hunyuan 为主** | 中文优化好、腾讯生态、成本可控；可配置切换 DeepSeek/GLM |

### 2.3 安全设计

- **API Key 保护**：TokenHub API Key 仅存在云函数环境变量，客户端永不接触
- **内容安全**：复用现有 `msgSecCheck` 云函数，对用户输入和 LLM 输出双重审核
- **未成年人保护**：对话中加入心理风险评估，检测到自伤/自杀倾向立即触发关怀流程并推荐专业资源
- **数据脱敏**：测定记录存储前去除敏感个人信息

## 三、核心功能模块

### 3.1 对话式测定引擎（核心）

#### 核心理念：叙事追踪，而非场景测试

测定不是"问 8 个功能各一道题"，而是**让用户讲自己的故事，从真实的思维轨迹中识别认知功能**。

传统场景库的问题：预设问题 → 用户预判意图 → 回答失真。而真实的生活叙事中，认知功能的运用是自然流露的——一个人讲述冲突时的关注点、做决定时的考量方式、回忆往事时调用的细节，这些都是功能栈的真实信号。

#### 双框架测定：荣格八维 + 九型人格

测定同时识别两个独立的人格维度，因为它们测量的是不同层面：

| 框架 | 测量层面 | 用户可见度 |
|------|---------|-----------|
| **荣格八维** | 你如何思考（信息处理 + 决策方式） | 主展示：功能排序 + 置信度 |
| **九型人格** | 你为何行动（核心动机 + 恐惧 + 欲望） | 轻提示：仅显示类型编号 |

九型人格含三层结构：
- **主型 (1-9)**：核心恐惧与欲望，决定根本动机
- **侧翼 (w)**：相邻类型的修饰，如 4w5 / 4w3，影响表达方式
- **副型 (sp/sx/so)**：自保 / 一对一 / 社交，影响能量投向

> 用户端只轻微显示九型主型（如"你的九型倾向：4 号"），侧翼和副型不展示，仅在云端完整分析和关系对比中发挥作用。

#### 测定流程设计

```
阶段 1: 暖场 + 故事邀请 (2-3 轮)
  ↓ 引导用户分享近期生活、困惑或成长经历
  ↓ 例："最近有什么事让你印象深刻，或者一直在想？"
  ↓ 用户自然展开叙事——这是分析的原始素材

阶段 2: 叙事追踪追问 (8-14 轮) ← 核心
  ↓ LLM 从用户叙事中同时识别两类信号：
  ├── 认知功能信号 → 追问思维过程（HOW）
  │   "你当时是怎么想到这个的？" → Ne/Ni
  │   "那一刻你主要考虑了什么？" → Te/Ti/Fe/Fi
  └── 九型动机信号 → 追问行为动机（WHY）
      "你做这件事时，最怕发生什么？" → 核心恐惧
      "如果这件事成了，对你意味着什么？" → 核心欲望
  ↓ 每轮追问都锚定用户自己提到的生活细节，不用模板题

阶段 3: 信号验证与补充 (2-4 轮)
  ↓ 对叙事中未自然覆盖的维度，用用户自己的情境延伸追问
  ↓ 认知功能补充 + 九型侧翼/副型信号验证

阶段 4: 云端综合判定
  ↓ LLM 输出完整分析：
  │   • 荣格八维：功能证据链 + 置信度 → MBTI 类型
  │   • 九型人格：主型 + 侧翼 + 副型 + 动机证据链
  ↓ 存云端，用户不可见完整分析
  ↓ 用户端收到：八维功能排序 + 置信度 + 九型主型（轻微提示）

阶段 5: 成长建议 + 学习路径引导
```

#### 叙事信号识别框架

**荣格八维信号**（HOW — 信息处理与决策方式）：

| 认知功能 | 叙事中的信号特征 | 追问方向 |
|---------|----------------|---------|
| **Se** | 描述具体感官细节、现场氛围、即时反应 | "当时那个画面/声音/感觉，你还记得吗？" |
| **Si** | 调用具体记忆、对比过去经验、关注细节一致性 | "这让你想起以前类似的经历吗？" |
| **Ne** | 联想跳跃、提到多种可能性、发散关联 | "你说到这个，还联想到什么？" |
| **Ni** | 直接给出结论/洞察、关注深层含义和走向 | "你当时是怎么一下子想明白的？" |
| **Te** | 关注效率、结果、组织安排、客观标准 | "你当时是怎么安排/推进这件事的？" |
| **Ti** | 分析原理、追求逻辑自洽、质疑前提 | "你觉得这件事最关键的逻辑是什么？" |
| **Fe** | 关注他人感受、群体氛围、维护和谐 | "当时其他人是什么反应？你怎么应对的？" |
| **Fi** | 强调个人价值观、真实性、内在感受 | "这件事对你个人来说意味着什么？" |

**九型人格信号**（WHY — 核心动机与恐惧）：

| 九型 | 叙事中的动机信号 | 追问方向 |
|------|----------------|---------|
| **1 号** | 关注对错、改进、标准、"应该怎样" | "你觉得这件事怎样才算'做对了'？" |
| **2 号** | 关注他人需求、被需要感、付出 | "你帮了别人之后，心里是什么感觉？" |
| **3 号** | 关注形象、成就、目标达成 | "这件事做成了，别人会怎么看你？" |
| **4 号** | 关注独特性、真实感受、缺失感 | "你觉得自己和别人不一样在哪里？" |
| **5 号** | 关注理解、知识储备、边界感 | "你需要先搞清楚什么才会行动？" |
| **6 号** | 关注安全、确定性、忠诚、质疑 | "你当时最担心的是什么？" |
| **7 号** | 关注可能性、体验、逃避痛苦 | "除了这件事，你还想做什么有趣的？" |
| **8 号** | 关注掌控、力量、公正、直接 | "你当时是怎么面对这个压力的？" |
| **9 号** | 关注和谐、和平、避免冲突 | "你当时是怎么处理这种不舒服的？" |

**侧翼与副型信号**：
- 侧翼（w）：主型叙事中混入相邻类型的特征 → 追问细节确认倾向
- 副型（sp/sx/so）：
  - sp 自保：叙事围绕安全感、资源、身体舒适
  - sx 一对一：叙事围绕亲密关系、深度连接、吸引力
  - so 社交：叙事围绕归属感、地位、群体角色

> 注意：以上表格是 LLM 的内部识别框架，**不会作为固定问题抛给用户**。LLM 根据用户实际叙事内容，判断出现了哪些信号，再决定追问什么。

**九型人格的可见性策略**：
- **展示**：主型编号（一行文字，如"你的九型倾向：4 号"），不展开理论
- **不展示**：侧翼（w）、副型（sp/sx/so）、核心恐惧/欲望描述、九型详细理论
- **用途**：九型的完整结果（含侧翼副型）仅在云端分析和关系对比引擎中使用，用户感知到的是"系统还考虑了更多维度"，但不了解具体机制

**为什么这样设计**：
1. **保护用户**：详细分析可能引发过度解读或自我标签化，尤其对抑郁群体有害
2. **专业价值**：完整分析对咨询师理解用户有高价值，是商业化的重要资产
3. **保持神秘感**：关系对比方法论不公开，增加付费解锁详细版的价值感
4. **合规考量**：心理相关分析数据不应无门槛展示，符合内容审慎原则

#### 角色权限体系

| 角色 | 可见内容 | 获取方式 |
|------|---------|---------|
| **普通用户** | 自己的八维排序 + 置信度 + 成长建议 | 完成测定即获得 |
| **认证咨询师** | 授权用户的完整分析记录 + 证据链 | 后台认证 + 用户授权 |
| **管理员** | 全部脱敏数据 + 统计分析 | 后台权限 |

> 注：不区分家长/孩子角色，所有用户走同一套流程。家长和孩子都是"普通用户"，各自独立完成测定、查看自己的结果。关系分析功能（基于现有 mbtiRelations.js）仍然保留，任意两个用户可对比功能栈互动，但不作为独立的产品模块。

#### Prompt 工程核心设计

测定引擎的 System Prompt 结构（云函数中维护）：

```
你是一位受过荣格心理学和九型人格理论训练的人格测定师。你不是在"测试"用户，
而是在和用户聊天中，从他们讲述的真实生活故事里，识别其认知功能模式（HOW）
和核心动机模式（WHY）。

【核心原则】
1. 绝不使用预设问题清单——每轮追问都锚定用户刚刚提到的具体生活细节
2. 像一个好奇的朋友一样倾听，然后追问"你是怎么想的""那一刻你关注了什么"
3. 同时识别两类信号：
   - 认知功能信号（HOW）：关注感官细节 vs 可能性联想 → Se/Si vs Ne/Ni
                           关注效率结果 vs 逻辑自洽 → Te vs Ti
                           关注群体和谐 vs 内在价值 → Fe vs Fi
   - 九型动机信号（WHY）：核心恐惧是什么？核心欲望是什么？行为背后的驱动力
4. 每轮回复自然温暖，不超过 150 字，像聊天而非访谈
5. 不要让用户感觉在被测试——感觉在被理解
6. 检测到心理危机信号时，优先关怀，暂停测定

【追问策略】
- 用户讲了冲突事件 → 追问决策依据（功能信号）+ 最怕什么发生（九型信号）
- 用户讲了人际故事 → 追问情感处理方式（Fe/Fi）+ 帮助他人的动机（2号?）
- 用户讲了困惑/思考 → 追问思维过程（Ne/Ni/Te/Ti）+ 想搞清楚什么（5号?）
- 用户讲得抽象 → 追问具体细节（验证 Se/Si）
- 用户讲得具体 → 追问深层含义（验证 Ni/Ne）+ 这件事对ta意味着什么（4号?）
- 某维度信号已充分 → 不再追问该方向，转向未覆盖维度
- 用用户自己的生活情境延伸追问，不引入陌生场景

【荣格八维叙事信号识别】
- Ni: 跳过推导直接给结论、关注"这件事意味着什么"
- Ne: 联想跳跃、提到"这让我想到..."、发散多种可能
- Si: 回忆具体细节、对比"以前怎样现在怎样"
- Se: 描述现场画面感强、关注即时反应
- Ti: 分析内在逻辑、质疑"这真的合理吗"
- Te: 关注怎么执行、安排、达成结果
- Fi: 强调"对我个人来说"、表达真实内心感受
- Fe: 关注别人怎么看、群体氛围、他人反应

【九型人格叙事信号识别】
- 1号: 关注对错/标准/改进，常说"应该"
- 2号: 关注他人需求/被需要感，主动付出
- 3号: 关注形象/成就/目标，在意他人评价
- 4号: 关注独特性/真实感受/缺失感，觉得自己不同
- 5号: 关注理解/知识/边界，需要先搞清楚才行动
- 6号: 关注安全/确定性/忠诚，常质疑和担忧
- 7号: 关注可能性/体验/逃避痛苦，追求有趣
- 8号: 关注掌控/力量/公正，直接面对冲突
- 9号: 关注和谐/和平/避免冲突，化解不舒服

【侧翼识别】主型叙事中混入相邻类型特征（如4号叙事中有5号的withdrawn倾向→4w5）
【副型识别】
- sp自保: 围绕安全感/资源/舒适
- sx一对一: 围绕亲密/深度连接/吸引力
- so社交: 围绕归属/地位/群体角色

【输出规范】
每轮对话后，在内部（用户不可见）更新各功能置信度 + 九型置信度评估。
当 8 功能中至少 6 个置信度>0.6 且九型主型置信度>0.7，或对话达 18 轮时，
输出结构化分析结果（含双框架证据链），由云端保存。
用户端只展示：功能排序+置信度等级+九型主型编号，不展示证据、分析过程、
侧翼副型、对比方法论。

【荣格八维判定规则】
- 主导+辅助功能决定 MBTI 前两字母的能量方向
- 判断功能(T/F)在主导或辅助位 → J 型（若外倾）/ P 型（若内倾）
- 感知功能(S/N)在主导或辅助位 → P 型（若外倾）/ J 型（若内倾）
- 主导功能内倾 → I 型；主导功能外倾 → E 型
```

### 3.2 关系对比引擎（MBTI × 九型组合）

#### 设计理念

关系对比不再只看 MBTI，而是**结合 MBTI 认知功能栈 + 九型人格动机层**进行双维度分析。两个框架互补：
- MBTI 对比：你们的思维方式和信息处理如何互动
- 九型对比：你们的核心需求和恐惧如何碰撞

用户看到的对比报告是综合结果，但**不透露分析方法和九型细节**——用户感知到的是"这个分析很深"，但不了解背后的机制。

#### 缓存策略

因为人格组合是有限的，对比报告可缓存复用：

```
缓存键：mbti1_enneagram1 ↔ mbti2_enneagram2
  mbti: 16 种
  enneagram: 主型(9) × 侧翼(2) × 副型(3) = 54 种
  单人 profile: 16 × 54 = 864 种
  无序配对: 864 × 863 / 2 ≈ 37 万种

实际策略：懒加载缓存
  - 首次请求某组合 → LLM 生成报告 → 存云数据库
  - 后续相同组合 → 直接返回缓存（毫秒级）
  - 热门组合（如 INFJ-4w5sx × ENFP-7w6so）优先预生成
```

> 绝大多数组合永远不会被请求到，懒加载避免了无意义的预计算。实际活跃组合预计在数千量级，云数据库完全可承载。

#### 对比报告分层

```
┌──────────────────────────────────────────────────┐
│            简单版（免费）                          │
│                                                   │
│  • 关系类型标签（如"深层共鸣""互补成长"）          │
│  • 一句话关系概述                                 │
│  • 整体契合度指示器（3 档：轻松/需磨合/有挑战）    │
│  • 1-2 条互动小贴士                               │
│                                                   │
│  ✗ 不含：分析方法、九型细节、功能栈对比逻辑        │
├──────────────────────────────────────────────────┤
│            详细版（付费解锁）                      │
│                                                   │
│  • 深层互动模式分析                               │
│  • 潜在冲突点与成因（不透露判定依据）              │
│  • 成长互补方向                                   │
│  • 沟通策略建议（具体场景）                       │
│  • 压力下的互动模式预警                           │
│  • 3-5 条个性化互动指南                           │
```

**关键：不透露方法论**
- 报告用"你们之间"的描述性语言，不用"因为你的Ni和他的Ne..."
- 用户感受到分析深度，但不知道系统是怎么算出来的
- 这既保护了产品的核心壁垒，也避免用户过度理论化解读关系

### 3.5 目标人群专项设计

#### 针对"休学/抑郁"群体的特殊考量

**安全优先原则**：
1. **开场关怀**：对话开始前展示心理支持信息，提供专业求助渠道
2. **语气调节**：LLM 对话风格设为温暖、非评判、不催促
3. **危机检测**：实时检测自伤/自杀相关表达，触发分级响应
4. **结果呈现**：避免病理化标签，强调"认知风格"而非"问题"
5. **退出自由**：任何时刻可暂停，进度自动保存

> 注：不区分家长/孩子角色。休学/抑郁状态的青少年和家长都是产品的用户，各自独立完成测定、查看自己的结果。对话风格统一为温暖陪伴式，侧重自我探索，不做角色区分。任意两个用户（如家长和孩子）可基于现有关系算法对比功能栈互动，但这只是通用功能，不作为独立模块。

## 八、已确认决策

| 决策项 | 结论 |
|--------|------|
| AI 能力 | **微信云开发内置 AI**（wx.cloud.extend.AI），无需 TokenHub |
| 旧测试 | 完全移除 quick-test/test，对话测定为唯一入口 |
| 测定方式 | 叙事追踪追问（非固定场景题库） |
